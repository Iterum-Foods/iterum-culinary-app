# 🍳 Iterum Culinary R&D App - Complete Project Overview

## 📋 Project Overview

**Iterum Culinary R&D App** is a comprehensive, AI-powered culinary management platform designed for professional kitchens, chefs, and food service professionals. It serves as a digital notebook and complete kitchen management system for recipe development, menu planning, inventory management, and culinary innovation.

### **Core Purpose**
Transform culinary creativity into reality by providing a professional-grade platform for:
- Recipe research and development
- Menu planning and costing
- Inventory and vendor management
- Kitchen operations and workflow management
- Multi-user collaboration with project-based organization

### **Key Differentiators**
- **Offline-First Design**: Full functionality without internet connection
- **User-Controlled Data**: Complete data ownership with local storage
- **Ingredients-Centric Architecture**: All systems built around a master ingredients database
- **Enterprise Security**: AES-GCM encryption, XSS protection, CSP headers
- **Multi-User Support**: Project-based organization for teams and clients

## 🏗️ Architecture

### **System Architecture: Ingredients-Centric Design**

The application follows an **ingredients-centric architecture** where the Ingredients List serves as the foundation for all other systems:

```
┌─────────────────────────────────────────────────────────────┐
│                    INGREDIENTS LIST                          │
│              (Master Database - Foundation)                  │
│  • Base ingredients (145+ professional items)              │
│  • Custom ingredients                                        │
│  • Standard units, categories, nutritional data             │
│  • Allergens, dietary info, substitutes                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ References
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      INVENTORY                               │
│         (Vendor Deliveries → Unit Conversion)               │
│  • Links to Ingredients List (ingredientId)                │
│  • Vendor units converted to ingredient standard units     │
│  • Quantity tracking, locations, par levels                 │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ Cross-references
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      ORDERING                                │
│         (Cross-referenced with Inventory)                   │
│  • Uses Ingredients List for item selection                 │
│  • Checks Inventory for current stock levels                │
│  • Generates orders based on par levels                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ Built from
                            ▼
┌─────────────────────────────────────────────────────────────┐
│              PREP RECIPES & PLATINGS                         │
│         (Built from Ingredients List)                        │
│  • Recipe ingredients reference Ingredients List            │
│  • Unit conversion for recipe quantities                   │
│  • Cost calculation from ingredient prices                  │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ Built from
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                        MENUS                                 │
│         (Built from Prep Recipes & Platings)                 │
│  • Menu items link to recipes                               │
│  • Recipes use ingredients from Ingredients List            │
│  • Menu costs calculated from recipe costs                  │
└─────────────────────────────────────────────────────────────┘
```

### **Key Architectural Principles**

1. **Ingredients List = Single Source of Truth**
   - All ingredients must exist in Ingredients List first
   - No orphaned ingredients in inventory, recipes, or menus
   - Standard units defined in Ingredients List
   - Ingredient IDs used as foreign keys throughout system

2. **Data Flow**
   - **Ingredients List** → Master database with standard units
   - **Inventory** → Vendor deliveries converted to standard units, linked via `ingredientId`
   - **Ordering** → Cross-references Inventory and Ingredients List
   - **Recipes** → Built from Ingredients List, deducts from Inventory
   - **Menus** → Built from Recipes, costs calculated from ingredient prices

3. **Storage Architecture**
   - **Primary**: IndexedDB + LocalStorage
   - **Cloud Backup**: Firebase Firestore
   - **User Isolation**: User-specific storage keys
   - **Offline-First**: Full functionality without internet

### **Data Storage Architecture**

#### **Multi-Layered Storage**
1. **IndexedDB** (Secure Storage Manager)
   - Fast, unlimited storage for large datasets
   - Optional encryption for sensitive data
   - Stores: Recipes, Ingredients, Projects, Menus, Cache

2. **LocalStorage** (User-Controlled Storage)
   - Primary storage for user data and metadata
   - ~5-10MB capacity
   - User-specific data isolation
   - Automatic backups every 5 minutes

3. **Firebase Firestore** (Cloud Sync)
   - Cloud backup and multi-device synchronization
   - Automatic sync when online
   - Offline queue for sync when offline
   - User-specific data isolation

4. **JSON Exports** (Manual Backups)
   - Human-readable backup format
   - Manual export/import functionality
   - Data portability

#### **Data Isolation**
All data is stored with user-specific keys:
```javascript
// Format: `{dataType}_{userId}`
`recipes_${userId}`
`menus_${userId}`
`equipment_${userId}`
`ingredients_${userId}`
`projects_${userId}`
```

### **Security Architecture**

1. **Data Encryption**
   - AES-GCM encryption for sensitive localStorage data
   - Optional XOR encryption for IndexedDB
   - Secure key generation and management

2. **XSS Protection**
   - Safe HTML injection using trusted content flags
   - Input sanitization for all user-provided content
   - Automatic escaping of potentially dangerous characters

3. **Content Security Policy (CSP)**
   - Strict CSP headers to prevent code injection
   - Violation monitoring and reporting
   - Real-time security event logging

4. **Input Validation**
   - Comprehensive validation for emails, passwords, text inputs
   - File upload security checks
   - Number and data type validation

5. **API Security**
   - Secure fetch wrapper with authentication tokens
   - Request sanitization and validation
   - Response integrity checks
